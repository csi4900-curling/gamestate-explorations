# Postscore left-view short-path rescue

This branch is **development on an exposed recording**. It cannot revise the frozen 79-candidate full-match result or supply an independent F1. The source-selected [path-censoring diagnostic](LEFT-RECALL-DIAGNOSTIC-PLAN.md) showed that extending four failed left-view windows from 12 to 20 s without changing thresholds recovered no path. Stored proposals show moving stones that slow and settle within about 1.5–2 m of their far-entry detection, while the original selector requires a 0.3 m forward step per 0.5 s sample and at least 2 m endpoint travel.

Apply one uniform candidate-side rescue to **all 60 left-view corridor candidates**, using the existing 12 s held-registration observations. Preserve any path already selected by the frozen gap/dropout pipeline. Only for candidates with no selected path, rerun the unchanged far-entry path algorithm with `min_forward_step_m = 0.15` and `min_travel_m = 1.0`; keep 0.5 s sampling, 0.6 s maximum gap, entry `y <= -4.5 m`, at least four samples, and all other kinematic limits. Accept only a unique returned path. Do not alter right-view candidates. This is a deliberately permissive **proposal** stage, so run the same frozen three-patch stone-appearance screen and shared-timed-path duplicate removal on all 116 corridor IDs before comparing results.

Preserve source and code hashes, every candidate ID, the original full-match output, the nine prospective short-path additions, and every abstention. Source-review newly accepted cases without using those reviews to tune this branch. Report both gained candidates and any evidence of false positives. Independent, exhaustive labels on a different recording remain necessary before claiming improved recall or acceptable precision.
