# Can a second camera corroborate early corridor throw proposals?

The saved high-recall left-camera corridor proposals were joined to the existing full-match right-camera proposal inventories. The join checks colour, image travel direction, and camera order: for `positive_y` the right passage precedes the left; for `negative_y` it follows. A right proposal must be within 20 seconds. If one right proposal is compatible with multiple left proposals, both left proposals are marked ambiguous. This is **proposal-level temporal corroboration**, not verified tracking of one physical stone.

The [feature runner](../../../../prototype/scripts/audit_corridor_right_corrob.py) reads no reference labels. The [separate scorer](../../../../prototype/scripts/score_corridor_right_corrob.py) compares those frozen features with the existing same-agent coarse delivery windows. Both recordings and the 20-second window were exposed during development, so these results are diagnostic only.

| Exposed interval | Earlier high-recall proposals | Unique right match among coarse-window matches | Unique right match among unmatched proposals | Hypothetical unique-match-only gate |
| --- | --- | ---: | ---: | --- |
| [Canada–Estonia](../../canada-estonia-2024/corridor-right-corrob-score-postreview.json) | 17 TP / 5 FP / 0 FN | 16 / 17 | 0 / 5 | 16 TP / 0 FP / 1 FN; F1 0.970 |
| [Canada–Italy](../../canada-italy/corridor-right-corrob-score-postreview.json) | 17 TP / 7 FP / 0 FN | 17 / 17 | 1 / 7 | 17 TP / 1 FP / 0 FN; F1 0.971 |

In Estonia, the remaining matched proposal and one unmatched proposal share a right candidate; four unmatched proposals have no right candidate. In Italy, six unmatched proposals have no right candidate, but one unmatched proposal has a unique right match. Thus a strict gate improves these in-sample point scores but **cannot satisfy both perfect recall and precision even on these two exposed intervals**. A missing right match may mean right-camera detection failure rather than no throw; a time-compatible right match may be a person or a different stone. We retain the feature as confidence/review evidence, not a hard filter.

The references are sparse, same-agent, coarse delivery windows. Their 17 events per interval are not independently certified exhaustive continuous-video ground truth. These numbers say nothing about full-match performance or unseen camera layouts. To promote a two-view filter, the system needs object-level stone/person discrimination, physical-identity linking across views, duplicate handling, explicit abstention for occluded or absent views, and independent full-recording labels.

The later prediction-only episode exports preserve shared-right and right-only candidates without turning them into confirmed throws: [Estonia](../../canada-estonia-2024/corridor-right-episodes-postreview.json) has one shared-right group and one right-only proposal; [Italy](../../canada-italy/corridor-right-episodes-postreview.json) has one right-only proposal. A filter score computed only from left candidates does not classify these right-only paths.

The prediction-only joins are [Estonia](../../canada-estonia-2024/corridor-right-corrob-postreview.json) and [Italy](../../canada-italy/corridor-right-corrob-postreview.json); each artifact records input and code hashes. Tests cover direction-dependent view order and shared-right ambiguity.

## Existing stone-patch model on matched right tracks

We then ran the previously trained, frozen [cross-match cap-patch model](../../../curlobserver-learned-probe/README.md) on the first, middle and last saved bounding box of every right track linked above. This [prediction-only feature runner](../../../../prototype/scripts/audit_corridor_right_patch_evidence.py) did not read the event reference or the source-pixel class. The [Estonia features](../../canada-estonia-2024/corridor-right-patch-evidence-postreview.json) contain 17 right tracks and the [Italy features](../../canada-italy/corridor-right-patch-evidence-postreview.json) contain 18. All 17 Estonia tracks and all 17 Italy tracks associated with a coarse-window match scored stone-like in all three frames. The Italy track paired with extra proposal S07 scored stone-like in only **one of three** frames; its separate, earlier source review calls it person/wheelchair/equipment.

The [postreview scoring runner](../../../../prototype/scripts/score_corridor_right_patch_diagnostic.py) evaluates a **hypothetical** unique-right-match plus three-of-three-patch rule. It yields [16 TP / 0 FP / 1 FN in Estonia](../../canada-estonia-2024/corridor-right-patch-score-postreview.json) and [17 / 0 / 0 in Italy](../../canada-italy/corridor-right-patch-score-postreview.json) against the coarse windows. Estonia's missed proposal S23 shares its right track with duplicate candidate S24, so the strict uniqueness condition abstains on both. The three-of-three aggregation was inspected after seeing these exposed tracks and is **not a frozen transfer result**. Even a positive patch only says the crop resembles a stone; it cannot prove that the candidate is a delivery or that two cameras observed one stone. Further tests must freeze the model, sampling and aggregation before each new recording, include all candidate/negative intervals, and check recall as well as precision.

## Frozen same-family cross-recording check

The fixed rule was subsequently applied to the previously exposed [Canada–China development interval](../../canada-china-2024/CORRIDOR-RIGHT-PATCH-TRANSFER-RESULTS.md), with source/model/code hashes recorded before its right-camera scan. Temporal corroboration alone retained all 18 coarse-window matches and removed the seven extras. **The three-of-three patch gate retained only five matches and missed 13.** This directly overturns any suggestion that the Estonia/Italy appearance result generalizes within the same production family. It reinforces using patch scores as graded evidence while preserving throw candidates when appearance is weak or unavailable. The China result remains same-agent, partial-interval development evidence, not independent full-match validation.
