# Frozen public stone boxes at 2024 passage crossings

The [full-track context transfer](TRACK-CONTEXT-TRANSFER-RESULTS.md) left
object identity unresolved. A separate
[crossing-box probe](../../../../prototype/scripts/audit_public_boxes_at_crossings.py)
tests two **unchanged** models trained on the public CurlObserver image/clip
labels: the earlier [image model](../../../curlobserver-learned-probe/model-v2/model.npz)
and revised [clip model](../../../curlobserver-learned-probe/public-tracking-v2/model.npz).
For each source-selected passage, it searches for a same-colour accepted box
whose centre is within 15 px of the tracked crossing in the source frame at
−0.2, 0 and +0.2 s. A nearby box is only a detection observation, not a
verified delivery or physical identity.

| Exposed, prediction-targeted source cases | Image model: any nearby box | Clip model: any nearby box |
| --- | ---: | ---: |
| Scotland bridge, five clear stone crossings | 2 / 5 | 3 / 5 |
| Scotland bridge, four clear non-stone crossings | 0 / 4 | 0 / 4 |
| Scotland bridge, one occluded/uncertain crossing | 0 / 1 | 0 / 1 |
| Latvia ranked accepted, four clear stone crossings | 0 / 4 | 1 / 4 |
| Latvia ranked accepted, one clear player crossing | 0 / 1 | 0 / 1 |
| Latvia isolated-withheld, two clear player crossings | 0 / 2 | 0 / 2 |

The [Scotland probe](scotland24-bridged-development/public-box-crossing-probe.json),
[Latvia accepted-case probe](latvia24-full-v1/public-box-accepted-probe.json),
and [Latvia withheld-case probe](latvia24-full-v1/public-box-withheld-probe.json)
contain every sampled decision, raw colour proposal count, source hash,
model hash and exact code hash. Source crossing crops and the limitations of
the agent-selected cases are documented in
[Scotland's crossing review](CROSSING-PATCH-FAILURES.md) and the
[Latvia context transfer](TRACK-CONTEXT-TRANSFER-RESULTS.md).

The public model's standard colour proposal generator requires contour area
at least 15 px² in a 640×360 frame. At the selected Latvia crossings, the
visible yellow S35 cap produces a roughly 9.5 px² same-colour contour and
therefore **no standard proposal**. The clear red S96 and S38 stone crossings
have no same-colour contour within 15 px under its fixed HSV mask at the exact
crossing frame. Other misses occur **after** proposal generation: Scotland's
S59 has 12 nearby raw red box proposals in each of the three frames but no
accepted box from either model. Red S181 also has proposals in one sample and
no accepted box. A reproducible [small-cap diagnostic](latvia24-full-v1/small-cap-diagnostic.json)
that lowered the contour-area floor from 15 to 3 px² and tried 8–24 px
boxes still left S35's best clip-model score (about 1.28) below the frozen
model threshold (about 1.34). It produced no local same-colour contour for
S96 or S38. This is a selected development probe generated by
[`probe_small_cap_proposals.py`](../../../../prototype/scripts/probe_small_cap_proposals.py),
not a proposed threshold change.

The models reject the selected player/wheelchair cases but would suppress at
least **five of nine** source-visible stone crossings if used as a hard
same-colour crossing gate (clip model; seven for the image model). Those
selected counts are not a generalizable recall estimate. The event ledger is
unchanged. The next verifier needs small-stone proposal recall and a body/ice
contact check that works in this broadcast side view, followed by complete
match, independent event scoring before any hard veto is promoted.

A separate [crossing-darkness transfer](CROSSING-DARKNESS-TRANSFER.md) tested
a simple source-pixel body/ice cue suggested by the selected Latvia cases.
It failed on Scotland: the fixed cut would reject four of five reviewed
visible stone crossings. This cue is also not a hard event gate.
