# Candidate motion rescue: exposed 2024 development fit

The receiver-path filter now has a **label-free rescue stage** for passage candidates that lack a unique far-to-house path. It preserves every path accepted by the prior rule. For a rejected candidate only, it permits a bounded gap through a registration abstention or a registered frame with no distant same-colour cap proposal. It still requires kinematically plausible stone motion from the far region. A right-view path may first appear at y≥11.5 m, 0.5 m later than the previous gate. When the longest paths share a substantial observed prefix but diverge near the end, it retains only that prefix as event evidence and explicitly marks later identity unknown. A frozen cap-patch model screens each selected path, and equal timed paths are deduplicated.

This rule was **designed after inspecting Italy, Estonia, and China errors**. The scores below are in-sample development fits against exposed, coarse, same-agent source windows. They do not revise the earlier [frozen Italy transfer](CANADA-ITALY-2024-REPAIRED-MOTION-TRANSFER-RESULTS.md) of 14/0/3 or the [frozen Estonia transfer](CANADA-ESTONIA-2024-MOTION-TRANSFER-RESULTS.md) of 6/0/11.

No reference window is read by the motion or screen runners; scoring occurs afterward.

The Italy rescue adds S03, S18, and S19. S03 is **shared-prefix evidence**, not a verified whole path: competing paths share five moving observations before diverging. The first/middle/last cap-patch scores are −0.27, +0.36, −0.20, so the frozen one-positive rule accepts it, but the margin is modest. S18 and S19 have stronger positive samples. Estonia keeps its prior 18 provisional paths and removes duplicate S24 because it shares timed observations with S23. China proposes one new motion path, D05; its three patch scores are −0.82, −1.10, −0.82, so the screen rejects it. The already known jersey-leaf false path D11 also fails the patch cue.

A [broader dropout experiment](china-estonia-italy-far-band-dropout-postscore.json) that applied bridging to **every** candidate was worse: previously valid paths became ambiguous and false paths appeared. The implemented rescue preserves prior accepted paths and applies the new bridge only when the old rule abstains. A separate [entry-gate sensitivity test](italy-estonia-entry-gate-sensitivity-postscore.json) showed that simply moving the gate admitted false Italy S14 and made true S31 ambiguous. These negative controls explain the final rule's conditional structure; they are not independent validation.

The path still depends on source-specific calibration and a small appearance model. A missing coloured-cap proposal is an observation failure, not proof of an unobstructed physical path. The longest shared prefix can support a throw event while later stone identity, collisions, release/settle time, and the full post-throw board remain unknown. The next required gate is to **freeze this exact code and thresholds before another recording**, run candidate generation and the complete screen unchanged, and score against independent exhaustive labels where available. A full-match, cross-camera-family test is still needed before using its output as simulation-ready game state.
